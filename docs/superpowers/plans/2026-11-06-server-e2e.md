# Server E2E CI Implementation Plan

> Use superpowers:executing-plans to implement the tasks in order.

**Goal:** Run fixed real-image regression checks against the built server in CI.

**Architecture:** A shared TypeScript HTTP checker owns the fixtures and prediction assertions. A separate runner starts the built server with temporary configuration, waits for health, invokes the checker, and always stops its child. Existing Vitest tests cover checker failures; actual E2E and deliberate failure runs verify the process lifecycle.

**Tech Stack:** Node.js 22+, tsx, Vitest, GitHub Actions.

**Spec:** https://github.com/misskey-dev/sensitive-detector/issues/38

## Global Constraints

- Commit redistributable 299×299 PNG fixtures with source, license, and expected class.
- Five unique classes, finite probabilities in [0, 1], expected class strictly highest; no exact probabilities.
- Missing images/model fail; startup limit 120 seconds, HTTP limit 60 seconds.
- Always terminate the server, including errors and signals.
- Reuse the HTTP checker from Docker issue #39. No production API or release workflow changes.

## Review Focus

- Health connection attempts and body reads must remain bounded by the startup deadline.
- Failed inference and malformed responses must fail even when HTTP status is 200.
- Child exit, spawn errors, cancellation, and assertion failures must release the process and temporary files.
- Fixture licenses and expected classes must have independent provenance.
- E2E must not resolve the application entrypoint to source or skip missing inputs.
