# Docker CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PR時にamd64・arm64のDockerビルドと、ビルドしたイメージ自身の起動・画像推論を検証する。

**Architecture:** CIの独立matrixジョブがイメージをローカルにロードし、既存configだけを読み取り専用でマウントする。TypeScriptの検証コマンドがDockerのHEALTHCHECKと公開ポートを確認し、#38の画像・検証処理を再利用する。診断と削除はworkflowの独立した終了ステップで行う。

**Tech Stack:** GitHub Actions, Docker Buildx, Node.js 22, TypeScript/tsx, Vitest.

**Spec:** https://github.com/misskey-dev/sensitive-detector/issues/39 （会話で合意済みのIssue 2）

## Global Constraints

- amd64は`ubuntu-24.04`、arm64は`ubuntu-24.04-arm`。QEMUは使用しない。
- PR、mainへのpush、workflow_dispatchで実行する。
- 起動待ちは最大120秒、HTTPリクエストは応答本文を含め最大60秒。タイムアウトは失敗する。
- モデルはイメージ同梱。既存`config.docker.mjs`のみを`/config/config.mjs`にreadonlyでマウントし、テスト用APIキーを環境変数で渡す。
- `/health`の200、組み込みHEALTHCHECKのhealthy、実画像の期待予測、認証なし401を全て必須とする。
- 失敗時はコンテナログと状態を出力し、成功・失敗・キャンセル時とも削除ステップを実行する。
- レジストリへのログイン・push、公開API、本番の判定仕様、リリースworkflowは変更しない。

## Review Focus

- healthyにならない・早期終了・HEALTHCHECK欠落を成功と誤認しない。
- 応答ヘッダーのみ到着し本文が止まったHTTPも時間制限を守る。
- 認証不要になった推論APIや異なる予測を成功にしない。
- build/start/checkのどこで失敗しても診断・削除ステップが実行される。
- 各runnerでビルドしたイメージ自身を起動し、ホストのモデルで同梱漏れを隠さない。
